# Changelog

## Unreleased

### Added
- `VerifyOptions.photon` names the Photon jar or directory of jars the IMF pass runs, ahead of `PHOTON_DIR` and the cache directories, so a caller that already resolved Photon its own way (imfwizard reads `PHOTON_JAR` and `--photon-jar`) no longer needs a second variable set for the pass to run. The field is not read from the REST body, since it is a classpath the server would execute.

### Changed
- `serve` binds `127.0.0.1` by default, where it bound `0.0.0.0`: without `--api-key` the endpoint validates any path the process can read, so it is no longer reachable from other hosts unless `--bind` says so.

### Added
- `scripts/fetch_photon.sh`, imfwizard's checksum-pinned Maven Central fetch, and a CI step that runs it on the Linux, macOS and Windows runners with a JDK and a cache, so `PHOTON_DIR` is set for every test run. Nothing exercised the Photon pass in CI before, which is how a parser that dropped all of Photon's output survived. The test tools step now also demands `java -version`.
- CLI tests that build a real SMPTE DCP, ffmpeg-encoded JPEG 2000 picture essence and a PCM tone wrapped by asdcplib, and run `qc-report`, `diff`, `diff --fingerprint`, `frame-compare` and `validate --timeline` over it. CI installs weasyprint on the Linux and macOS runners so the PDF report is written and checked rather than assumed.

### Added
- `serve --api-key <key>`, or `DCPDOCTOR_API_KEY` in the environment, requires that key in `X-Api-Key` or `Authorization: Bearer` on every request but `GET /health`. The endpoint hands a caller-named path to the validator and the default bind address is `0.0.0.0`, so until now anything that could reach the port could ask the process to read any directory it can read. The key is compared without stopping at the first differing byte, and is checked before routing, so an unauthorized caller learns nothing about which paths exist. Without a key the server logs a warning at startup.

### Fixed
- `watch` on Windows validated a package while an asset was still being written: the directory listing it measured keeps the size and modification time from the last close, so a file open and growing looked unchanged between two polls. Every file is now stat'd directly.

- Every EBU R128 figure `loudness` and `qc-report` printed was the value at the first tenth of a second, not the measurement: ffmpeg's ebur128 filter prints a running `I:` and `LRA:` on every progress line and the parser took the first match in the output, so a track measuring -20.0 LUFS was reported as -70.0 LUFS with a 0.0 LU range. Both values now come from the filter's `Summary:` block, and ffmpeg output carrying no summary is an error rather than a number.

- The QC report's Track Files table never filled its UUID column, called a sound track and a picture track both "essence", and rounded every size to whole megabytes, so a 580 KB sound track read as 0 MB. Each file now carries the asset id the package's own ASSETMAP gives it, its type is `picture`, `sound` or `metadata`, and a track under a megabyte is sized in KB. A title, client name, file name or error message containing `&` or `<` is escaped, which it was not, so the report no longer stops parsing as HTML at that character.

- `validate --html` wrote every finding's message and file path into the page unescaped, and findings quote element names, so `has no <Hash> in the CPL` reached the browser as an unknown open tag and the rest of the row went missing. One `escape_markup` now covers the validation report, the QC report and the timeline SVG.

- `diff --fingerprint` read ffprobe's stream entries by position while ffprobe emits them in its own order, so the fingerprint's width was the height, its height was zero, and the frame count was the picture width: a package whose picture is shorter than its width in frames (2048 frames is 85 seconds at 2K) sampled a frame that does not exist and reported "Fingerprint unavailable". The entries are read by key now, the frame count falls back to the duration times the frame rate when the MXF container declares none, and the sampled frame is pulled straight from ffmpeg's stdout rather than through a shell pipeline into `xxd`, which is not installed everywhere. The diff also prints whether the two are the same picture, at the 0.1 normalized Hamming distance the comparison now names.

- `frame-compare` reported "No frames compared" and exited 1 for every DCP and IMP, so the PSNR/SSIM/VMAF comparison worked on no real package: postkit's stats parsers required ffmpeg's luma component keys and picture essence decodes to RGB, which ffmpeg names `psnr_r`/`psnr_g`/`psnr_b` and `R:`/`G:`/`B:`. Fixed in postkit 9f06b51, pinned here. The verdict was wrong on top of that: `IDENTICAL` meant "no frame below the 30 dB PSNR threshold", so a re-encode of the same content measuring 62.78 dB and 0.9929 SSIM was reported as an exact match. `IDENTICAL` now means every frame came back lossless, a package that differs but clears the threshold reads `WITHIN THRESHOLD`, and one that does not reads `DIFFERENT`, each with the count of frames under the threshold. Exit codes are unchanged.

- The `--timeline` SVG carried no timecode, only a frame count and a reel number, and an ampersand in the content title made it unparseable. Each reel bar is now labelled with its duration as a timecode at the reel's own edit rate, with a `<title>` for the hover text, the total carries one too, and the title text is escaped.

- `fix --dry-run` previewed a different thing from what `fix` does: it listed `fixes::suggest_fixes` entries derived from the validation notes, which named repairs `fix_dcp` does not perform and missed ones it does. Both run `fix_dcp` now, under `FixMode::DryRun` or `FixMode::Apply`, so the preview is the repair list with the writes skipped, and a dry run exits 0 because it changed nothing. The `fixes` module had no other caller and is gone.
- `fix` rewrote an asset's `<Hash>` and left its `<Size>`, so a package it repaired failed validation on `pkl_size_mismatch`. Both are rewritten now, each inside its own `<Asset>` element. `fix` also exited 1 listing errors its own repairs had just cleared, a wrong CPL namespace and the schema violation that namespace causes among them: when it has written something it re-reads the package, without re-hashing it, and keeps only the findings that still stand.
- Nothing reported a CPL whose root namespace disagrees with the asset map's, so the Interop and SMPTE namespace repair `fix` advertises was unreachable on a DCP: the only notes with those codes came from subtitle documents. `validate` reports `smpte_namespace_wrong` on an Interop CPL in a SMPTE package and `interop_namespace_wrong` on the reverse, naming the CPL, which is the file `fix` rewrites.
- `serve` parsed HTTP itself: one 8 KiB read per connection, routes matched by `request.starts_with("POST /validate")`, and the body taken as whatever followed the first blank line. A request whose head and body arrived in separate packets lost its body and answered "missing path", a body over 8 KiB was truncated, `POST /validate-nothing` reached the validate handler, and connections were served one at a time with no timeout, so one client that opened a socket and stopped writing blocked every other caller. It runs on postkit's `RestServer` now: a real request line and header parser, exact path matching, a 1 MiB body cap answered with 413, a 30 second read and write timeout, and a thread per connection. A body that is not a validation request is a 400 naming the problem, an unknown field in it is a 400 rather than a silently empty path, and a path that does not exist is a 404 naming it. `POST /verify` stays as the legacy spelling that takes `dcp_dir`.
- `serve` exited 0 when it could not bind: the failure went to a log line and the process returned. It prints the address and the error and exits 1.
- `watch` validated a package the moment its folder appeared with an `ASSETMAP`, so a package still being copied in was reported as failing on whatever bytes had landed, and the real verdict never followed: the folder was already in the seen set. A package is validated now only once every file its asset map names is present and its file count, total size and newest modification time match the previous pass, so a copy in progress is left alone and each package is reported exactly once. The seen set was also never pruned, so a package deleted and copied in again was ignored; state for a folder that has left the directory is dropped. Watching moved out of `server.rs` into `watch::watch_directory`, with `DirectoryWatch::poll_once` as the single pass a test can drive.
- `tests/fixtures/valid_smpte`, the package every hash, diff and repair test starts from, failed `validate` with three `xml_schema_violation` errors: the asset map had no `VolumeCount` or `Issuer`, the PKL put `Creator` before `IssueDate`, and the CPL put `ContentTitleText` before `IssueDate` and carried neither `ContentVersion` nor `RatingList`, with `Duration` before `EntryPoint` in both reel assets. Nothing asserted the package passed, so a fixture named valid was never valid. The three documents follow ST 429-9, ST 429-8 and ST 429-7 element order now and the package reports PASS, which is what the watch and repair tests assert.
- `a_supplied_kdm_satisfies_the_kdm_required_check` handed `check_encryption` the system temp directory, and that check counts any file whose name contains "kdm" as the package's KDM, so an unrelated file in `/tmp` failed the test. It writes its CPL into its own directory now.
- `validate` printed PASS for an IMP whose track file was missing, altered or truncated, and for one with no PKL at all: the IMF path ran the CPL checks and Photon only, never the ASSETMAP file-exists, PKL `Size` and PKL `Hash` checks the DCP path runs. Both paths call the same two functions now, so an IMP fails on `asset_not_found`, `pkl_size_mismatch` and `pkl_hash_mismatch` the way a DCP does, `--no-hashes` gates the IMF hashing the same way, and an IMP with no readable `ASSETMAP.xml` says so instead of skipping all three. Two parsing defects fed the same hole: any XML containing the string `PackingList` counted as a PKL, so an ASSETMAP (which carries `<PackingList>true</PackingList>` on its PKL asset) stood in for a deleted PKL, and a CPL `Resource` filled its track file id from whichever of `SourceEncoding` and `TrackFileId` came first, which in ST 2067-3 element order is `SourceEncoding`, the essence descriptor's id, so no ASSETMAP asset matched it and every MXF essence check on that resource was skipped. A PKL is found by its root element now, `SourceEncoding` has its own field, and the EssenceDescriptor cross-reference follows it. A CPL resource `Hash` that disagrees with the PKL's is reported as `cpl_pkl_hash_mismatch`, as on the DCP path.

- Every finding Photon prints was dropped on the floor: the parser read lines beginning `ERROR:`, `FATAL:` or `WARNING:`, and Photon 5.0.1 logs through slf4j-simple, so a finding reads `[main] ERROR com.netflix.imflibrary.app.IMPAnalyzer - ERROR-<message> [Photon version: 5.0.1]`. `validate` printed PASS on an IMP whose CPL Photon had just rejected. Both forms parse now, each note carries the document named on the INFO line above the finding, the version suffix that repeats on every line is trimmed, and a Photon run that threw partway (a truncated track file does it) reports `check_skipped` instead of contributing nothing. The unit tests are Photon 5.0.1's own stderr, pasted from a run.

- `auto-qc --black-threshold` was handed to ffmpeg's `pixel_black_th`, the luma below which a pixel counts as black, while its default 0.98 is `picture_black_ratio_th`'s default, the share of a frame that has to be black. A flat mid-grey frame was reported as a black frame. The flag now sets the pixel threshold and defaults to ffmpeg's 0.10, the picture ratio stays at 0.98, and a 20% grey run is reported only when `--black-threshold` is raised past it.

- `auto-qc` decided silence from the whole file's per-channel RMS, so it fired only on a track that is silent end to end and never on a silent stretch inside one: a second of digital silence between two seconds of tone reported nothing. Silence now comes from ffmpeg's `silencedetect` at the `--silence-threshold` given, and a run in a real AS-DCP sound track file is reported as `Audio silence from 1.00 s to 2.00 s`.

- `auto-qc` named no position for anything it found, printing `Black frames detected: 1 segment(s)`. Every black, freeze and silence run now names the seconds it covers, and a run reaching the end of the file says so. The detectors moved into `dcpdoctor-core::auto_qc`, black and freeze read out of one decode rather than two, and `--json` exits 1 on findings as the text output already did.

- `av-sync` had no notion of a reel or a package: it took one video file and one audio file and subtracted the two container durations ffprobe reported, so the per-reel drift the docs describe could not be measured at all, and a package whose second reel enters its sound twelve frames late looked identical to a clean one. It now takes a DCP or IMP directory and compares each reel's picture and sound as the CPL declares them, reporting the entry-point offset and the duration difference per reel in frames and milliseconds at that reel's edit rate. The file pair form stays for a loose video and WAV. A reel with no sound asset, or one whose duration or entry point is no integer, is listed as not compared rather than counted as in sync.

- `--atmos` could not detect a real immersive audio track file and invented the object count for anything it did flag. It ran ffprobe, which lists no stream at all for ST 429-18 Dolby Atmos data essence or for ST 2067-201 IAB, and then decided "Atmos" from a channel count of 16 or more, so a 16-channel PCM sound track file was reported as Atmos while an Atmos track file was not. The object count was the channel count minus a 12-channel bed, or, failing that, the first packet's size minus 2048 divided by 200. Detection now asks asdcplib for the essence type and reads the descriptor: a DCP Atmos track file reports the MaxObjectCount, MaxChannelCount and version its DolbyAtmosSubDescriptor declares, an IMF IAB track file is reported as detected with no object count, since its descriptor carries none, and a PCM track file draws nothing. The sample rate and bit depth notes are gone: Atmos data essence carries neither, so both fired on every Atmos file. Over 118 objects is still an error. The check no longer needs ffprobe, so it runs when ffprobe is absent.

- `hdr-validate` never read a MaxCLL or MaxFALL, so `--max-cll` and `--max-fall` could not fail: the regexes matched `max_content:` and `max_average:` while ffprobe writes JSON members, `"max_content": 1000`, and the closing quote stopped every match. The mastering display regex looked for `min_luminance=<digits>` and ffprobe writes `"min_luminance": "50/10000"`, so that never matched either. All four parse now, and the test drives an HDR10 clip ffmpeg wrote with `max-cll=1000,400`.

- `--hdr` decided the transfer function from ffprobe's mapping of the essence descriptor, and read `bt2020-10` and `bt2020-12`, the SDR BT.2020 transfers, as HLG. BT.2020 primaries alone, with no transfer at all, set the type to PQ, so a BT.2020 SDR track file was reported as HDR. The transfer and the primaries now come from the descriptor ULs through asdcplib, ST 2084 and the ST 2067-21:2020 HLG label each read as bytes, with ffprobe kept as the fallback for anything that is not a JPEG 2000 track file.

- `--hdr` reported no MaxCLL or MaxFALL for any DCP or IMP, and so checked neither: it looked for them in the picture MXF, where they are not. ST 2067-21 clause 7.5 puts them in the CPL's ExtensionProperties, which is where postkit's IMF writer puts them, and no MXF essence descriptor asdcplib reads or writes has an item for either. They are read from the CPL now and reported beside the transfer as `hdr_metadata_summary`. Three checks fire on them, all `hdr_metadata_invalid`: a MaxFALL above its MaxCLL is an error, since no frame average can be brighter than the brightest pixel; a MaxCLL above the mastering display maximum is a warning; and light levels on an HLG composition are a warning, clause 7.5 defining them for the PQ colour systems only. The HDR notes carried `picture_invalid_resolution` before, which would have read as a resolution defect.

- `profiles --check` printed PASS for a package it had read nothing from. The picture size and the channel count came from `info::get_dcp_info`, which reads both through ffprobe, so a run without ffprobe on PATH, or one whose MXFs would not open, compared 0x0 at 0 channels against every limit and passed. Both now come from the essence descriptors through asdcplib, the readers the playback checks already use, and a limit nothing was compared against is reported as INCOMPLETE with the reason it could not be read, with exit 1. The frame rate came from the EditRate numerator alone, so a 24000/1001 composition read as 24000 fps and broke every profile's maximum. Atmos presence was a file-size guess, any MXF over 1 MiB that ffprobe listed no streams for, so a large subtitle or auxiliary track failed the Barco, Christie and IMAX profiles on a format it does not carry: it is the essence type asdcplib reads out of the MXF header now, in `info` too. `max_bitrate_mbps` is deleted from the profiles rather than left advertised, since nothing ever measured a package's bitrate against it.

- `facility-check` never looked at a signature. A package signed with an expired certificate, or one whose signature no longer matches the document, was "Ready for delivery: YES". It now runs the CPL and PKL signature, chain and ST 430-2 certificate rules as a `Signing certificates` item, and a package where nothing is signed says that rather than passing quietly. Its PKL and CPL discovery matched any XML holding the string `PackingList` or `CompositionPlaylist` anywhere in the first 2 KiB, so an ASSETMAP (which carries `<PackingList>true</PackingList>`) stood in for a PKL that was never delivered: both are found by root element now. The hash item counted failures without naming any, so a report read "2 hash mismatch(es), 1 missing file(s)" with no way to tell which asset: it names each file and what was wrong with it.

- Every certificate rule silently did not run on a package whose XML signature binds the signature namespace to `dsig:`, which is what DCP-o-matic and the ISDCF reference DCPs write. The certificate extraction matched the literal prefixes `<X509Certificate` and `<ds:X509Certificate`, so `certificate_expired`, the chain linkage rules and all seven ST 430-2 rules in `cert_rules` saw an empty chain and reported nothing. Certificates are now collected by resolving the namespace, the way `has_signature` already did after the same defect was fixed there. The ISDCF reference CPL, whose signer certificate expired in 2023, is the fixture.


- `check_netflix_delivery` accepted any ApplicationIdentification containing the substring `2067-21` or `2067-20` (ST 2067-20 is Application 2, not the 2E Netflix takes), took an EditRate as valid if the string contained one of seven rates it listed, `48 1` among them, which App 2E does not allow at any picture format, and never looked at the CPL namespace at all, so a DCP CPL dropped in a folder passed as an IMF delivery. The rules are now the ones Netflix's own validator applies, each citing the Photon class it comes from and carrying the source URL in the note: exactly one file named `ASSETMAP.xml` at the package root (`BasicMapProfileV2MappedFileSet`), a CompositionPlaylist in one of the two ST 2067-3 namespaces Photon has a schema for (`IMFCompositionPlaylist`), an ApplicationIdentification that is one of the four App 2E URNs (`CoreConstraints.fromApplicationId`), and a composition EditRate among the App 2E frame rates (`IMFApp2E2020ConstraintsValidator`). The App 2E colour model, bit depth, stored size, frame layout and JPEG 2000 profile live in the essence descriptors, and the notes now say the Photon pass is what reads those instead of leaving the package looking fully checked. Findings carry `netflix_delivery_violation` rather than `missing_assetmap`.

- The ISDCF naming check never read the audio field, and found the resolution by looking for `2K` or `4K` anywhere in the title, so a name carrying `2K` in the studio field passed with no resolution of its own. Both fields are read where the convention puts them now, the audio field against the ISDCF registry's audio configurations (`10`, `20`, `21`, `51`, `71`, `MOS`, `IAB`, `AURO`, `DTSX`, `ATMOS`, each optionally followed by `HI`, `VI`, `SL` or `DBOX`) and the resolution field against `2K` and `4K`, and each names the token it rejected.

### Changed
- Leq(m) is measured on the ISO 21727 reference through postkit 13b5b33: the M weighting curve replaces the CCIR 468 one and the B-chain offset moves from 105.0 to 108.01 dB, so every `leq_m_db` the CLI and the QC report print is about 2.6 dB lower than 1.2.0 printed for the same track. dcpdoctor thresholds nothing on it, so no verdict changes.

## [1.2.0] - 2026-09-07

### Changed
- Version 1.2.0 puts DCP Doctor on the same release number as DCP Wizard and IMF Wizard, which ship together from now on.

### Fixed
- `validate --check-mxf` read every track file into memory twice, once for the partition scan and once for the header magic check, so a 23 GB feature picture MXF took 12 GB resident and was killed at the session's memory cap. Both reads are bounded now: the partition scan reads the first partition pack and the last 64 KiB, the magic check reads 16 bytes. A test counts the bytes the scan reads from an 8 MiB track file.
- `mxf_invalid_structure` reported a missing footer partition on every picture MXF whose footer index table is longer than 64 KiB, which is any feature: the check only scanned the last 64 KiB for the partition pack key. The footer offset now comes from the random index pack at the end of the file, confirmed by the partition pack found there, and the tail scan remains only for a file with no RIP.

## [0.5.1] - 2026-09-03

### Added
- App 2E picture descriptor checks on every MainImage track of an App 2E CPL, always on: `picture_not_imf_profile` (the codestream Rsiz is a DCI cinema or other non-IMF profile, so the samples are not the RGB an App 2E track carries), `picture_colour_missing` (ColorPrimaries or TransferCharacteristic absent from the RGBA descriptor), `picture_coding_label_mismatch` (the PictureEssenceCoding label is not the one the Rsiz calls for, nor its generic family label) and `picture_pixel_layout_mismatch` (the pixel layout depths or count differ from the codestream components). A header that will not read reports `check_skipped`. The cinema-profile X'Y'Z' IMPs imfwizard wrote before its `create` was fixed passed this validator, and are the negative fixture. The expected label comes from `jp2k::picture_essence_coding_for_rsize`, the AS-02 writer's own Rsiz to label table, asdcplib-rs 3948330 -> fd9d4a0 and postkit 8ea2f4a -> b2bb489 for the same pin.
- CI installs ffmpeg 8.1 and xmllint on the Linux, macOS and Windows runners, and checks all three binaries answer before the build. No test skips itself now when a tool is missing: the 11 tests that returned early without xmllint and the 2 that returned early without ffprobe fail instead, and the wasm J2K parser test reads a wrapped codestream committed under `tests/fixtures/mxf` rather than a path outside the repository.
- `check_skipped`: a check that should have run and could not now says so, naming the check and the reason. Introduced by an audit that removed every silent skip found in the codebase: "checked and clean" and "not checked" no longer look the same in any output.
- A GUI launch test, `tests/test_gui.py`, the one dcpwizard and imfwizard already run: the Tauri binary is started under a virtual display, the test waits for a window titled DcpDoctor that is at least 200 pixels on a side, reads that window's pixels until it holds more than one colour, then sends SIGTERM and requires a clean exit. CI's GUI job installs xvfb and xdotool and runs it after the release build, so a GUI that builds but will not open, will not paint, or hangs on shutdown now fails the run. `tauri.conf.json` gains `backgroundColor` `#0D0D0D`, the page's own background, which is what makes an unpainted window one flat colour.

### Fixed
- Every picture MXF opened as PCM sound during the MXF checks, twice, and asdcplib wrote `PCM file EditRate is not a supported value: 0/0` and `PCM EditRate not in expected value range.` to stderr each time, so `dcpwizard verify` and `validate --check-mxf` printed four error lines on a clean package. The two sound probes now ask asdcplib for the essence type first and open only PCM essence, as `mxf_asset_uuid` already did.
- `projector_4k_stereo_support` could never fire: it decided 4K by reading a `<Resolution>` element, which no CPL schema defines and no package carries. The picture size now comes from the stereoscopic picture MXF's stored width, read through the `PictureEssenceReader` the bitrate walk already opens 3D essence with, against the ST 429-2 Table 1 threshold the picture frame-rate check already uses. A stereoscopic reel whose essence will not read reports `check_skipped` rather than passing.
- Two `check_skipped` notes were INFO where the rest are warnings, so a check that did not run read as an ordinary observation: the DTS:X probe failing, and the marker-level codestream checks skipping when the ffprobe fallback left their fields unset. Both warn now, which is the severity `schema_validation_skipped` set for the policy.
- `main_sound_config_invalid` followed a closed label table and rejected the ISDCF Bv2.1 reference packages on `DBOX2`, the secondary D-BOX motion code stream. It now follows the ST 429-16 section 4.4.2.10 grammar, a soundfield token then a channel list of `-` or one-to-six-alphanumeric tokens, and warns on a well-formed label outside the ST 428-12 and ISDCF set instead of erroring. `DBOX2` joins that set.
- The JPEG 2000 sub-descriptor of every picture MXF the toolchain writes was zeroed: nothing parsed the codestream into the picture descriptor. asdcplib-rs ff29a31 -> 3fe0962 replaces `PictureDescriptor.component_count` with a `codestream: CodestreamHeader` that only `CodestreamHeader::parse` builds, so the SIZ, COD, QCD and CAP values reach the sub-descriptor. A file written through the AS-DCP writer now reads back Rsiz, image and tile sizes, per-component depth and subsampling, decomposition levels and quantization instead of zeros. postkit 455de77 -> a31427e for the same pin, which also refuses an AS-02 picture wrap of a DCI cinema codestream and one carrying no ColorPrimaries or TransferCharacteristic.
- Fabricated passes, each now a reported failure: `hdr-validate` read a file ffprobe could not open as SDR/BT.709 and passed it against default expectations, `check_netflix_delivery` printed PASS for a package whose CPLs were never read, `checksum-verify` reported "All checksums verified OK (0 asset(s))" on a PKL it could not parse and counted an asset with no readable Hash or Size as verified, `facility-check` said "Ready for delivery: YES" without ever verifying a hash (it now runs the PKL hash verification, and `--no-hashes` shows an explicit not-checked item), `av-sync` printed a drift of 0.0 ms when ffprobe was missing, and `auto-qc` reported a 0.0 dBFS peak for audio ffmpeg could not read and false clipping on silent channels (astats' `-inf` did not parse).
- Missing-tool skips now warn instead of thinning the run: without ffprobe an encrypted DCP read as unencrypted from `--studio`, 3D essence classified as 2D, `--hdr`/`--atmos`/`--dolby-vision`/`--prores` returned nothing at all, and the picture essence checks under `--check-mxf` silently did not run. The same for a missing or partial schema directory, a schema file absent for one document's type, and xmllint failures on the `schema-validate` and `kdm` paths.
- Unreadable input no longer passes as clean: a corrupt picture MXF skipped every codestream check, a cleartext frame that is not JPEG 2000 passed them, a corrupt subtitle or closed-caption MXF (and an unreadable loose XML asset) skipped every timed-text rule, an unreadable embedded font or one that resolves to nothing skipped glyph coverage, an unreadable CPL skipped the BV2.1 and HFR passes, and `dcp diff` called two packages identical while some assets were never compared.
- Parse failures no longer disable the checks reading the value: a PKL asset with no Id vanished from the size and hash checks, a garbage PKL `Size` or ASSETMAP `Length` read as "not declared", a garbage reel `Duration` or `EntryPoint` read as zero (an unparseable timed-text EntryPoint passed the must-be-zero rule), an ASSETMAP that stops parsing mid-file returned the ids read so far, and a truncated codestream marker walk passed the placement rules over the unwalked remainder. Each is an error now.
- `fix` no longer loses findings: a hash mismatch it could not repair, a repair helper that returned without writing, and a PKL write that failed after the fact all landed in neither "repaired" nor "skipped", so the summary read "Nothing to fix" while the defect remained. `checksum-verify` also parsed `ASSETMAP.xml` as a second PKL (it contains the string `PackingList`), turning a valid package into bogus hash failures once empty hashes stopped counting as verified.
- A KDM with no signature errors (`signature_invalid`): ST 430-1 requires KDMs to be signed and only CPL/PKL presence was checked. A KDM missing its validity window now warns instead of passing with an empty-dated INFO, a certificate with no dnQualifier fails the ST 430-2 thumbprint rule instead of skipping it, and an undecodable certificate blob in ds:KeyInfo breaks the chain instead of vanishing. An empty `ContentTitleText` reaches the ISDCF naming rules instead of gating them off.
- The peak-bitrate measurement failing (unopenable essence, zero duration) is reported instead of leaving only the container-average estimate, and the ffprobe fallback for codestream parameters says which marker-level checks its stub fields cannot support. `qc-report` renders the notes for a picture track it could not scan and a row for a loudness measurement that failed, instead of omitting the section.
- `auto-qc` reported audio channel numbers one too high: ffmpeg's astats already counts channels from 1 and the report added another.
- `fix` rewrote a PKL hash by replacing the first occurrence of the recorded hash text anywhere in the file, so a hash that also appeared in an earlier asset or an `AnnotationText` was rewritten instead. It now rewrites the `<Hash>` inside the `<Asset>` whose `<Id>` matches, and still reports the mismatch as unrepaired when that element does not carry the recorded text.
- Three `--studio` checks that could never fire are deleted rather than left advertised: reel continuity read a gap count nothing measured and a sync flag always true, the subtitle font pass filled neither its missing-font list nor its shortest-display time, and stereoscopic detection hardcoded the eye frame counts as matching, leaving a skip note for a check that did not exist. The equivalents that do measure stay: `subtitle_font_missing` and glyph coverage on the subtitle path, and the ST 429-10 reel checks on the core path.
- Deleted as dead: `validate_audio` (no callers), `schema_validate::validate_namespace` (no callers), the studio supplemental pair (never invoked, its trigger never set), and `facility-check`'s `--strict` flag with the never-read `expected_standard` option. The presence test matched the literal prefixes `<Signature` and `<ds:Signature`, so a package binding the signature namespace to `dsig:`, which is what DCP-o-matic and the ISDCF reference DCPs write, read as unsigned: nothing verified its signature and `unencrypted_dcp_not_signed` fired on a package that carries one. Detection resolves the namespace now, a KDM gets the by-Id verification its `ds:Reference` elements need (it had none), and postkit canonicalizes under the algorithm each signature declares (pin 8256659 -> 97c8e82), without which a document declaring the plain comment-free C14N and carrying an XML comment failed its digest. A document changed after signing errors as `signature_invalid`. That verdict means the document has not changed since it was signed, not that a trusted party signed it: the verifying key is the leaf certificate the document itself carries, and whether that chain is acceptable remains the `certificate_*` rules' verdict.

## [0.5.0] - 2026-08-22

### Added
- CPL and PKL identity (Bv2.1 §8.1): a SMPTE CPL's `AnnotationText` must be present (`missing_required_element`) and equal its `ContentTitleText` (`cpl_annotation_text_mismatch`), and a PKL packaging exactly one CPL must repeat that title as its own `AnnotationText` (`pkl_annotation_text_mismatch`). A PKL listing one asset id twice now errors as `duplicate_asset_id`, the rule the ASSETMAP already had.
- CPL metadata (Bv2.1 §8.6.1): a SMPTE CPL with no `CompositionMetadataAsset`, or one with no `VersionNumber`, now reports `missing_required_element` instead of being skipped.
- `cpl_active_area_invalid`: a `MainPictureActiveArea` with an odd width or height, or one larger than the picture essence the reel carries, errors.
- `cpl_invalid_language`: every `Language`, `MainSubtitleLanguageList`, `AdditionalSubtitleLanguageList` and `ReleaseTerritory` value in a SMPTE CPL is checked against the IANA subtag registry, so `Deutsch` where `de` belongs is caught rather than passing a grammar test.
- J2K TLM and POC checks on the native path: a codestream with no TLM marker errors as `j2k_missing_tlm`, and `j2k_poc_invalid` covers the POC marker count the profile fixes (none for 2K, exactly one for 4K), a POC in a tile-part header, and the two fixed 4K progressions' parameter values. The marker walk is shared with the browser build.
- `--deep-j2k` now runs the codestream checks over every frame instead of frame 0 only, in the same pass as the RDD 52 guard-bit scan, so a stream that goes non-conformant partway through is caught. Each finding reports once with the first offending frame and how many frames carried it.
- Codestream forensics, collected in the same per-frame pass `--deep-j2k` already runs: the first frame's parameters (dimensions, profile, decomposition levels, code-block size, transform, layers, progression, tiles, tile-parts, MCT, TLM and POC presence) become an INFO summary (`j2k_codestream_summary`) alongside the worst frame as a percentage of the DCI per-frame byte cap, and any later frame that departs from those parameters warns as `j2k_parameters_vary` with the first frame and the count. Stereoscopic essence is scanned too, both eyes of every edit unit, each eye against half an edit unit's cap. `dcpdoctor qc-report` gains a "Codestream forensics" section, one table per picture track.
- Codestream forensics on IMF packages: an IMP's AS-02 picture tracks are scanned frame by frame under `--deep-j2k` like a DCP's, reporting the same `j2k_codestream_summary` INFO and `j2k_parameters_vary` warning, and `qc-report` gains their forensics tables. The cinema-only rules do not run on IMF essence, which is not encoded to the DCI profile: no ISO 15444-1 cinema profile checks, no 0xFFFF legacy-decoder check, no RDD 52 guard-bit check, and no DCI per-frame byte cap in the summary or the report table.
- `partially_encrypted`: a composition mixing encrypted and clear essence now errors. Each asset is well formed on its own, so nothing caught it, and the result plays in part without a KDM.
- Playback compatibility warnings, which report what installed equipment will not play rather than what the specifications forbid: a frame rate of 25, 30, 48, 50 or 60 (`projector_frame_rate_support`, naming the rate to deliver instead where there is one), 4K 3D (`projector_4k_stereo_support`), and sound with other than 8 or 16 channels (`distributor_audio_channel_count`).
- `subtitle_font_too_large`: an embedded font over 640 kB warns. The Bv2.1 cap is 10 MB across every font in the asset, which a single font this size passes while still stalling playback.
- `closed_caption_interop_overlap`: Interop closed captions overlapping in time now error, since the format cannot say which of two simultaneous captions wins.
- Timed-text timing and structure (Bv2.1 §7.2.3, §8.3.2): a SMPTE document with no `<StartTime>`, or a non-zero one that shifts every cue in the reel, errors as `missing_required_element` / `subtitle_invalid_timing`; a timed-text reel asset with no `<EntryPoint>` or a non-zero one errors as `subtitle_entry_point` / `closed_caption_entry_point`; a cue running past the reel that holds it errors as `subtitle_overlaps_reel`; and across a composition, subtitles present on only some reels (`subtitle_missing_from_reel`), subtitle assets declaring different `<Language>` values (`subtitle_language_mismatch`) and reels carrying unequal numbers of closed captions (`closed_caption_count_mismatch`) all error.
- Timed-text content rules: a `<Text>` element with no content errors as `subtitle_empty_text` (whitespace counts as content, as in libdcp, so the one-space placeholder cue DCP-o-matic writes on reels without subtitles passes), a `<Font>` naming an id no `<LoadFont>` introduced errors as `subtitle_font_missing`, an Interop asset holding no cues at all errors as `missing_required_element`, more than one namespace on the document root warns as `subtitle_namespace_count`, and a SMPTE `<IssueDate>` outside `yyyy-mm-ddThh:mm:ss` warns as `subtitle_invalid_issue_date`. Within one caption cue, lines that mix vertical alignments or are listed out of their on-screen order error as `closed_caption_layout`.
- Timed-text size and identity rules (Bv2.1 §7.2, ST 429-5): a track file over 115 MB, embedded fonts totalling over 10 MB, or a closed-caption document over 256 kB report `timed_text_size_exceeded`; an MXF whose ResourceID does not repeat the document's `<Id>`, or which reuses its AssetID as either, reports `timed_text_id_mismatch`; and essence whose duration disagrees with the reel's `Duration` reports `cpl_mismatched_durations`. Closed-caption tracks are now parsed from the CPL reel and checked alongside subtitles.
- Timed-text rules run on encrypted essence when a KDM and recipient key are supplied, instead of skipping every subtitle and caption asset in an encrypted package. Where no key covers an asset the rules still skip, but the report now says so (`kdm_required`) rather than passing in silence.
- MXF-wrapped subtitles reach the structural rule set: the ST 429-5 document is unwrapped from the essence and given the same checks a loose XML asset gets, so a SMPTE package (where subtitles are always wrapped) is no longer limited to glyph coverage.
- Subtitle documents are schema-validated: SMPTE ST 428-7 timed text routes to the DCDMSubtitle XSD for the DCST namespace it declares (2007, 2010 or 2014) and Interop DCSubtitle to `DCSubtitle.xsd`, both loose and MXF-wrapped, so a schema-invalid subtitle now reports `xml_schema_violation` instead of passing.
- `schema_validation_skipped`: the XSD pass used to skip itself silently when the schema directory or `xmllint` was absent, so a machine without either reported a clean run with no XSD coverage. It now warns and names the reason.
- CPL asset hashes: every reel asset's `<Hash>` is now read and compared with the PKL's for the same asset, so a disagreement errors as `cpl_pkl_hash_mismatch` (libdcp MISMATCHED_PICTURE_HASHES / MISMATCHED_SOUND_HASHES) and an MXF-backed asset with no `<Hash>` warns as `cpl_missing_hash`. Servers that hash-check against the CPL rather than the PKL reject the first case.
- Encrypted IMF essence reads with the run's content keys: `validate --kdm --recipient-key` now reaches an IMP, so an encrypted AS-02 picture track gets the same `picture_bitrate_measured` peak/average and the same codestream forensics a DCP with a KDM gets. Where no key covers a track the report says so (`kdm_required`, INFO with no KDM, WARNING when the KDM does not carry the track's KeyId) instead of passing in silence.
- KDM digest rules the schema cannot express, all errors: a DeviceList `<CertificateThumbprint>` that does not decode to a 20-byte SHA-1 digest (`kdm_thumbprint_invalid`), the same for `<ContentAuthenticator>` when present (`kdm_content_authenticator_invalid`), and the DCI assume-trust marker (DCSS 9.4.3.5) sharing a DeviceList with a real device thumbprint (`kdm_assume_trust_conflict`). Checked against real DCP-o-matic KDMs, one per ISDCF formulation, under `tests/fixtures/kdm`.

### Fixed
- FFMC and FFEC are required under `--strict` only in a feature, which is the Bv2.1 scope, so a test or trailer composition carrying FFOC and LFOC no longer warns. LFMC, which no rule requires, is recommended rather than required.
- `kdm_required` no longer reports a missing KDM when one was supplied to the run (`--kdm`): it only looked for a file inside the package directory.
- Picture bitrate is no longer measured off encrypted frames. asdcplib returns ciphertext when it is given no content key, and an AES frame is longer than the codestream it carries, so an encrypted track without a KDM reported the wrapping's rate: on a DCP that fed the DCI limit verdict. Encrypted essence is now measured only where a key decrypts it.
- `cpl_invalid_language` no longer fires on a conformant `ReleaseTerritory`. A territory declaring the ST 429-16 UN M.49 scope carries a numeric code, which was being measured against the RFC 5646 region grammar and flagged every time. It is now checked only where libdcp checks it, outside that scope.
- The browser build rejected any POC marker as "not permitted for DCI", which is a false positive on every conformant 4K DCP: the 4K profile requires exactly one in the main header. It now applies the same per-profile rule as the native path.
- The accepted picture sizes were the 2K/4K containers only, so every standard scope DCP (2048x858, 4096x1716) drew a spurious `picture_invalid_resolution` warning under `--strict`. Both coded scope sizes are now accepted.

## [0.2.0] - 2026-08-13

### Added
- GUI keyboard shortcuts: Ctrl+O opens a DCP folder, Ctrl+Enter validates, Ctrl+1 to Ctrl+4 pick a results severity filter, Ctrl+, toggles preferences and Escape closes them. Ctrl+K opens an overlay listing them by category, where clicking a shortcut captures a new key combination (Backspace or Delete unbinds, Escape cancels, a combination already in use is refused and names its owner). Per-shortcut and global reset buttons restore the defaults, and changes persist across restarts.
- 4K frame rate (ST 429-2 §8.2 Table 1): picture essence wider than 2K must run at 24/1, 25/1 or 30/1, so a 4K track file at 48/1 errors as `picture_invalid_frame_rate` under `--check-mxf`. Monoscopic essence only, which is the scope of the requirement.
- IMF picture bitrate: an IMP's AS-02 picture track files are measured frame by frame like a DCP's, and the peak and average are reported as a `picture_bitrate_measured` info note under `--check-mxf`. No pass/fail: the 250 Mbps ceiling is DCI's and no IMF specification sets one.
- MainSoundConfiguration (ST 429-16): SMPTE CPLs are checked for the tag in CompositionMetadataAsset, its `<soundfield>/<channels>` value is parsed against the MCA/ISDCF label set (garbage like `None` errors as `main_sound_config_invalid`), and the declared channel count is cross-checked against the sound MXF's ChannelCount (`sound_invalid_channel_count`).
- FFOC/LFOC marker offsets: FFOC in the first reel must be 1 and LFOC in the last reel must be one less than that reel's duration, warned per libdcp wording (`marker_invalid`).
- First-subtitle timing (Bv2.1): warns (`subtitle_first_event_early`) when the first reel's first displayable timed-text event starts under 4s in. Only the first reel counts and empty placeholder subtitle assets are ignored, avoiding DCP-o-matic bug #2757. Reads MXF-wrapped ST 428-7 XML and handles both SMPTE tick and Interop editable-unit TimeIn forms.
- Timed-text content (Bv2.1 §7.2.5-7.2.7): every MainSubtitle and ClosedCaption asset is checked for line count (>3 lines), line length (subtitle 52 warn / 79 max, both `subtitle_line_length`; closed caption 32, `closed_caption_line_length`, error), minimum duration (`subtitle_duration`, 15 frames) and minimum gap (`subtitle_spacing`, 2 frames). Subtitle vs closed-caption limits are picked from the CPL asset type. Character counts are unicode scalar values, not bytes (DoM bug #3097). A `closed_caption_charset` INFO lists caption characters outside the ISDCF Doc 9 set (ISO 8859-1 plus U+266A). Reuses the plain-XML/MXF ST 428-7 extraction. (DoM #3149, #3151, #3153, #3158, #3097)
- Stereoscopic 3D (ST 429-10): the msp-cpl `MainStereoscopicPicture` form is now validated as a picture track (cross-refs, duration), the FrameRate = 2x EditRate relationship is checked, and the essence type is confirmed as stereoscopic J2K where the MXF is present.
- Auxiliary data (ST 429-18): an `aux_data_detected` INFO identifies each AuxData track (Dolby Atmos / IAB), enriched with the probed essence type, and a duration mismatch against the reel's picture errors as `cpl_mismatched_durations` (ST 429-2 §9.4). The aux asset's cross-refs and PKL hashes are covered by the generic asset checks.
- PKL `Size` is checked against the actual file size (`pkl_size_mismatch`), independent of `--no-hashes`.
- Leq(m) loudness (ISO 21727, CCIR 468-weighted): reported alongside EBU R128 in the `loudness` command (text + JSON `leq_m_db`) and the qc-report HTML table.
- `dcp_not_signed` (ClairMeta `check_dcp_signed`): an encrypted package (a CPL declares a `<KeyId>` or carries an `<EncryptedDocumentKey>`) whose CPL or PKL lacks a `<Signature>` now errors instead of only surfacing the milder `kdm_required`.
- `unencrypted_dcp_not_signed`: an unsigned unencrypted package warns under its own code. No SMPTE "shall" demands a signature there, so this stays a warning where ClairMeta errors.
- `assetmap_invalid_name` (ClairMeta `check_am_name`): the asset map file's name is checked against the standard its root namespace declares. ST 429-9:2014 Annex A.4 requires `ASSETMAP.xml` for SMPTE, so a wrong name errors; the Interop name `ASSETMAP` comes from an informative annex of the MPEG Interop asset map spec (§6.2) and warns.
- `assetmap_size_mismatch` (ClairMeta `check_assets_am_size`): a chunk's `Length`, when present, must equal the asset's size on disk (ST 429-9:2014 §7.4). The element is optional, so an asset map that declares none stays silent.
- `reel_edit_rate_mismatch`: a reel's MainMarkers, MainSubtitle, MainClosedCaption and AuxData EditRate is compared against the picture's. Warns rather than errors, since ST 429-2 §9.6.1 and §9.7.1 are the only per-asset-class EditRate equality rules and they name picture and sound. Sound and CompositionMetadataAsset have their own "shall" and are not covered here.
- `composition_metadata_asset_mismatch`: ST 429-16:2014 §4.4.1 binds the CompositionMetadataAsset's `EditRate` to the picture's and its `IntrinsicDuration` to the picture's `Duration`, both "shall", so a disagreement errors.

### Fixed
- The vendored `SMPTE-430-3-2006-ETM.xsd` had its UUID pattern facet split across a line, which is not a valid regular expression, so both KDM schemas failed to compile.
- The IMF PKL `HashAlgorithm` check matched on local name, so an element bound to the xmldsig namespace instead of the PKL one passed. `parse_pkl` now resolves namespaces and the check reports a wrong binding as `missing_required_element`.

### Changed
- The DCI picture bitrate limit is 250 Mbps at every resolution. The 500 previously applied to 4K has no source in DCI, ST 429-4 or ST 429-2: DCSS 4.3.3 caps a 4K frame at the same 1,302,083 bytes as a 24 fps 2K one. A 4K package between 250 and 500 Mbps now errors where it passed. The IMF path's separate hardcoded copy of the old split is gone, and the limit comes from `postkit::j2k::DCI_MAX_BITRATE_MBPS`.

- The SMPTE/Interop standard is derived from the ASSETMAP's root namespace instead of its filename, so a package whose asset map is named for the wrong standard is no longer validated as that standard. `AssetMap.is_smpte`, a substring test over the whole document, is removed in favour of the shared derivation.
- `cpl_invalid_edit_rate` for the ST 429-2 §8.1 composition edit rate no longer needs `--strict`. It is a plain "shall", and the wasm validator already ran it ungated.
- Removed `compliance::check_smpte_compliance` and the private helpers only it reached. It had no caller anywhere in the workspace, and its asset-map naming branch could never fire since it keyed off a `Standard` derived from the same file name it was checking. Every code it produced is still produced elsewhere.
- Schema validation (`xml_schema_violation`) is now on by default: the SMPTE/Interop XSDs are vendored under `schemas/` (from the ClairMeta set, with `catalog.xml`), so `DCPDOCTOR_SCHEMA_DIR` is no longer required. The env var still overrides, and a missing dir degrades to skip.
- Severity escalated to ERROR where SMPTE text uses "shall": `cpl_mismatched_durations` (ST 429-2 §9.4), `subtitle_font_missing` when the subtitle carries Text (ST 428-7:2014; image-only subs still warn), and a wrong subtitle DCST namespace (`smpte_namespace_wrong` / `interop_namespace_wrong`, ST 428-7).
- j2k / bitrate / frame comparison / Leq(m) now delegate to the shared `postkit` library; the DCI-validation and note layers stay app-side. The AS-DCP jp2k reader is OP-Atom only, so IMF AS-02 / OP1a picture MXFs fall back to the ffprobe-derived path.
- Bumped asdcplib pin to `6d7b8ca` (adds `pcm::mca_labels`); postkit pinned at `8b4a034`.
